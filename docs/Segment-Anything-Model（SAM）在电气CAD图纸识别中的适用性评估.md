# Segment Anything Model（SAM）在电气 CAD 图纸识别中的适用性评估

> **调研日期**：2026-08-08  
> **结论摘要**：SAM / SAM 2 对本项目可作为“已知候选区域的精细轮廓提取、版面辅助分区、人工校正工具”，但不应作为电气元器件分类、主图框/表格区域判定或当前识别主链路的替代品。当前不建议直接接入生产识别流程；建议先开展离线小规模基准验证。

---

## 1. 调研问题

当前流程已从 DXF 中识别主图框，并在图框内执行：

1. 原生 `INSERT` / Block 识别；
2. 分类目录中的 DXF 矢量模板匹配；
3. 对没有可靠矢量候选的图框，按 CAD 视口切片后调用 VLM 或 OBB；
4. 将结果映射回 CAD 坐标并在前端展示。

本次问题是：**Segment Anything Model（SAM）的小型模型是否能帮助继续把大主图框拆分为电气图纸区域、表格区域，并提升元器件识别？**

---

## 2. SAM / SAM 2 是什么，不能做什么

### 2.1 能力边界

SAM 是提示驱动（点、框、掩码提示）的通用图像分割模型：输入图像和提示，输出对象像素掩码；也支持不加语义标签的自动掩码生成。它输出的是“哪里是一个视觉区域”，不是“这是什么电气元器件”。

SAM 2 将能力扩展到视频和图像；静态图像仍可使用点或框提示生成掩码。其核心新增价值是视频时序记忆，当前项目以单张 DXF 渲染图为主，因此这部分能力没有直接收益。

**关键限制：**

- SAM 不进行元器件类别分类，不能直接输出 `circuit_breaker`、`transformer` 等本项目的 15 个业务类别。
- SAM 不读取或结构化表格文字，不代替 OCR、原生 `TEXT/MTEXT` 解析或表格单元格重建。
- 自动掩码没有业务语义；在黑白、细线、高密度的 CAD 图中，可能将网格线、导线、文字、符号碎片分别切出，也可能把相连线网合成一个大区域。
- SAM 的训练和公开主张面向自然图像/视频的通用视觉分割，并非面向 DXF 渲染图、工程制图符号或 CAD 表格结构。因此 CAD 电气图上的效果必须实测，不能从自然图像指标外推。

### 2.2 “小模型”的含义

SAM 2.1 提供 `hiera_tiny`、`hiera_small`、`base_plus`、`large` 等检查点；官方模型描述列出的参数规模分别约为 38.9M、46M、80.8M、224.4M。`hiera_tiny` 虽是较小版本，但仍需要 PyTorch 推理环境，并非适合浏览器端或 CPU 实时运行的轻量传统图像算法。

官方安装说明还指出 SAM 2 依赖 Python $\ge 3.10$、PyTorch $\ge 2.5.1$、TorchVision $\ge 0.20.1$，并推荐 GPU；Windows 上推荐 WSL。故其运行时依赖明显重于当前的 DXF 矢量解析和模板匹配路径。

## 3. 与当前项目的匹配分析

### 3.1 当前已有能力与缺口

项目已具备：

| 当前模块 | 已有能力 | 与 SAM 的关系 |
|---|---|---|
| 主图框检测 | 基于闭合/拼接 `LWPOLYLINE` 的大矩形检测 | SAM 不是替代品；CAD 矢量规则更可审计、更稳定。 |
| CAD 切片 | 对主图框规划重叠 CAD 视口并直接高 DPI 渲染 | 可作为 SAM 的输入，但也会放大推理成本。 |
| DXF 模板匹配 | 已分类模板的平移、旋转、缩放几何匹配 | SAM 可在模板候选框内细化轮廓，不能替代类型判定。 |
| VLM / OBB | 输出业务类别及候选框 | SAM 可作为后处理，但没有类别输出，不能单独替换检测器。 |
| 表格接口 | 当前接口仍返回空列表 | SAM 可辅助找表格外边界；表格结构化仍必须由网格和文字逻辑完成。 |

### 3.2 对“电气区 / 表格区继续拆分”的价值

**直接使用自动掩码生成器：价值低，风险高。**

- 主图框已经是 CAD 矢量对象；表格通常是规则网格。通过 `LINE` / `LWPOLYLINE`、重复行列间距、闭合单元格数、文字密度即可得到可追溯的表格候选。
- SAM 的自动掩码很可能把导线、器件线段、文字轮廓、表格网格分别切碎；仍需要重新聚合，且结果不如直接利用原始 DXF 几何可解释。
- 主图框内的“电气图区域”往往是“主图框减去表格和标题栏”，可能是多个矩形或 L 形，并不是 SAM 擅长定义的自然对象边界。

**作为边界复核器：有条件价值。**

当矢量表格检测得到候选外框但存在扫描图、PDF 栅格化图或 DXF 转换丢失部分网格线时，可把表格候选框作为 SAM 的 box prompt，让其产出更细的像素掩码，再用于：

- 估计栅格图中的实际表格边界；
- 去除候选框外的文字/图线；
- 在前端人工审核时允许用户点选或框选区域后获得更精确的遮罩。

这只是**候选框细化**，不能作为表格判定依据；最终仍应按 CAD 坐标映射、网格和文字规则确认。

### 3.3 对元器件识别的价值

| 场景 | 价值 | 建议 |
|---|---|---|
| 用 SAM 从整张图自动找全部元器件 | 很低 | 不建议。无类别、细线容易碎裂、导线会干扰分割。 |
| 用 OBB/VLM/模板输出候选框后，SAM 精修器件轮廓 | 中低 | 仅在标注或像素级掩码确有业务需求时验证。当前前端和领域模型只需框与 CAD 中心点。 |
| 矢量模板候选的几何复核 | 低 | 模板匹配本身直接使用 DXF 几何，通常比渲染后再分割更可靠。 |
| 人工校正某个候选的真实边界 | 中等 | 可作为后续人工审核工具，不属于当前 P0 主路径。 |
| 训练 OBB 的标注辅助 | 中等 | 可用于半自动生成候选多边形，再经人工修订；需明确 SAM 输出不是真值标签。 |

## 4. 方案对比：表格与电气区拆分

| 方案 | 输入 | 输出 | 对当前 DXF 的可解释性 | 成本 / 风险 | 推荐度 |
|---|---|---|---|---|---|
| **DXF 网格规则** | 原始线段、多段线、文字坐标 | 表格矩形、行列线、单元格 | 高 | 低 | **优先实施** |
| **表格候选 + SAM 2 Tiny 复核** | 候选框对应的高 DPI 渲染图 | 像素掩码 | 中 | 中；需 GPU / 依赖 / 实测 | 仅试验 |
| 全图 SAM 自动掩码 | 主图框 PNG | 无语义掩码集合 | 低 | 高；后聚合困难 | 不建议 |
| VLM 直接判断版面类型 | 图块 / 切片 | 文本标签或框 | 低到中 | 依赖服务稳定性，可能幻觉 | 只作疑难复核 |
| 已训练布局分析模型 | 栅格图 | 表格/文本/图/标题栏类别框 | 中 | 高；需标注与训练/评测 | 真值集充足后评估 |

## 5. 推荐路线

### 5.1 不将 SAM 接入当前在线主识别链路

原因：

1. 当前的首要问题是将主图框按语义拆成表格、标题栏和电气图区；DXF 的规则网格与原生文字是更直接、可审计的信号。
2. 当前需要的是类别、位置和证据；SAM 仅给轮廓，不给类别和表格语义。
3. 现有流程已经包含模板/VLM/OBB 以及 CAD 视口切片。再增加 SAM 会提高 GPU、PyTorch、模型权重和审计复杂度，却不能消除 VLM/OBB 的类别缺口。
4. `SAM2.1-hiera-tiny` 仍会显著增加 Windows 本地部署难度；官方推荐 Windows 使用 WSL。

### 5.2 建议优先实现：DXF 语义版面分区

在每个已识别主图框内执行：

1. 合并水平、垂直 `LINE` / `LWPOLYLINE` 边段。
2. 找到具备重复行列间距的网格候选，计算闭合单元格数量、文本密度和面积。
3. 将高分候选写为 `table_region`；标题栏可依据位置、尺寸和标题类文字写为 `title_block_region`。
4. 用“主图框减去表格/标题栏”生成一个或多个 `electrical_region` 工作区。
5. 仅对 `electrical_region` 执行模板、VLM、OBB 与进一步 CAD 切片；将表格区域交给原生文字+网格单元格重建。
6. 在审计结果持久化每个区域的 `kind`、`cad_extent`、判定分数、网格证据及所属 `frame_index`。

建议的表格候选评分：

$$
S_{table}=0.40S_{grid}+0.25S_{spacing}+0.20S_{cells}+0.15S_{text}
$$

其中 $S_{grid}$ 为水平/垂直有效边比例，$S_{spacing}$ 为行列间距重复性，$S_{cells}$ 为闭合单元格密度，$S_{text}$ 为区域内文字密度。阈值应由真实图纸验证，不应在无样本的情况下固定。

### 5.3 若要验证 SAM：限定为离线 PoC

建议只验证 `SAM2.1-hiera-tiny`，并采用严格的失败门槛：

1. 选取 $20$--$30$ 个已人工标注的主图框，包含常见表格、标题栏、密集一次图、无表格图。
2. 先运行 DXF 网格规则生成表格候选框；不得用 SAM 全图自动掩码作为主候选来源。
3. 将候选框作为 SAM box prompt，比较 SAM 掩码外接框与人工表格外框的 IoU。
4. 记录：表格边界 IoU、误把电气区覆盖为表格的比例、平均耗时、峰值显存、每图框失败率。
5. 只有在以下全部成立时，才考虑做可选复核器：
   - 边界 IoU 显著优于纯 DXF 规则；
   - 不降低电气元器件区域召回；
   - 推理资源满足部署环境；
   - 失败时可无损回退到纯 DXF 规则。

建议验收指标（待真值集建立后调整）：

$$
\operatorname{IoU}_{table} \ge 0.90,\qquad
\operatorname{false\_mask\_electrical} \le 1\%,\qquad
\operatorname{latency}_{frame}\text{ 可接受}
$$

在缺乏上述证据前，不应将 SAM 掩码作为切掉电气区的依据。

## 6. 集成注意事项（仅在 PoC 通过后）

若进入可选集成阶段，应采用独立适配器，不污染现有矢量主路径：

- 新增 `recognition/sam_region_refiner.py`，输入渲染图和已有候选框，输出掩码/外接框以及模型、检查点、耗时、置信度元数据。
- 不将 SAM 掩码直接转换为元器件类别；类别仍必须来自 Block、模板、OBB 或 VLM。
- 不在 `backend/.venv` 中无评估地安装重量级 Torch/SAM 依赖；先建立隔离实验环境或 GPU/WSL 评测环境。生产依赖需在 PoC 通过后再评估。
- 使用 `sam2.1_hiera_tiny` 时仍需记录检查点哈希、PyTorch/CUDA 版本和 GPU 型号。
- 将超时、显存不足、模型未配置作为可观测降级，不影响原有 DXF 表格/电气区规则。
- 保持所有区域输出在 CAD 坐标系中，保存从渲染像素到 CAD 范围的变换，以便前端叠加和审计。

---

## 7. 最终结论

SAM 的价值不在于“让系统识别电气元器件”，而在于有提示条件下获得更细的**视觉边界**。对于本项目的核心 DXF 输入，表格、标题栏和电气区拆分应优先利用已有的矢量图元、网格结构和原生文字；这比全图 SAM 自动分割更可靠、成本更低、也更容易将结果映射回 CAD 坐标。

因此：

- **当前推荐：不接入 SAM 作为主链路。**
- **近期优先级：实现主图框内的 DXF 语义版面分区。**
- **可选后续：用 SAM 2 Tiny 对“已由规则提出的表格候选框”做离线边界复核 PoC，或作为人工标注/审核辅助。**
